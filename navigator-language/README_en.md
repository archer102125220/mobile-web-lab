# Navigator Language Cross-Platform Testing Laboratory 🧪🌐

Cross-Platform (iOS WKWebView, Android WebView, Mobile Safari, Chrome for Android, and Desktop Browsers) Locale Detection, Preference Resolution, and HTTP `Accept-Language` Negotiation Benchmark Suite.

[繁體中文版](README.md)

---

## 🔬 Goals & Experimental Scope

1. **Client-Side JS Locale Detection**:
   - Measure `navigator.language`, `navigator.languages` array lengths and return order.
   - Comprehensive ECMAScript 402 `Intl` API resolution (`DateTimeFormat`, `NumberFormat`, `DisplayNames`, `PluralRules`, `Collator`).
2. **Server-Side HTTP Header Verification**:
   - Live parsing of raw `Accept-Language` headers and q-factor descending weight sorting.
   - Analysis of `User-Agent` and Client Hints (`Sec-CH-UA-Platform`).
3. **Dual-Platform Native vs. Web Discrepancy Matrix**:
   - **iOS**: Compare System Locale, iOS 13+ Per-App Language, `Locale.preferredLanguages`, and WKWebView synchronization.
   - **Android**: Compare Android System Locale, `LocaleList.getDefault()`, and Android WebView internal resolution.
4. **Language Negotiation Simulator**:
   - Implements RFC 4647 Lookup & Base Language Matching algorithm to visualize real-world i18n fallback decisions.
5. **Dynamic Event Listeners**:
   - Live stream of `window.addEventListener('languagechange')` events and mock override simulations.

## 🚀 Quick Start

### Step 1: Start the Node.js Web Server

```bash
cd navigator-language
node server.js
```

Upon launch, the server will output local and LAN URLs in the terminal, and automatically write configuration files to iOS (`ServerConfig.swift`) and Android (`env.properties`):

```text
======================================================================
🧪 Navigator Language & Locale 雙平台測試伺服器已啟動！
======================================================================

💻 Local URL:
   👉 http://localhost:3000
   👉 http://127.0.0.1:3000

📱 Mobile Device & WebView (Ensure connection to the same Wi-Fi):
   👉 http://192.168.1.100:3000  (en0)
======================================================================
```

---

### Step 2: Choose Testing Method

#### Option A: Mobile Browsers (Mobile Safari / Chrome)
1. Ensure your phone is connected to the same Wi-Fi as your computer.
2. Scan the on-screen QR Code using your phone camera or enter the LAN URL.
3. The dashboard will automatically activate "Mobile Browser Mode".

#### Option B: iOS WKWebView Shell
1. Open `navigator-language/IOS/NavigatorLanguageDemo.xcodeproj` in Xcode.
2. Run on an iPhone Simulator or physical device.
3. The app will automatically connect and export iOS Native `Locale.preferredLanguages` via `NativeBridge`.
4. **Test Case**: Go to iPhone Settings > NavigatorLanguageDemo > Preferred Language to switch languages and observe WKWebView vs Native values.

#### Option C: Android WebView Shell
1. Open `navigator-language/Android` in Android Studio.
2. Run on an Android Emulator or physical device.
3. The app will automatically connect and export Android `LocaleList.getDefault()` via `NativeBridge`.
4. **Test Case**: Go to Android Settings > System > Languages & input > Languages to reorder languages and observe WebView reaction.

## ⚖️ Comparison Cheat Sheet

| Dimension | iOS (WebKit) | Android (Chromium) |
| :--- | :--- | :--- |
| **Primary Language** | `navigator.language` reflects system/app preference | `navigator.language` reflects system/Chrome preference |
| **Languages Array** | `navigator.languages` contains full user preference list | `navigator.languages` contains system/Chrome ordered list |
| **Per-App Language** | iOS 13+ seamlessly inherited into WKWebView | Android 13+ requires context locale synchronization |
| **HTTP Headers** | Automatically includes q-factor `Accept-Language` | Automatically sends quality-weighted `Accept-Language` |
